# Project & Task Management System

## Database Schema

Database: MongoDB  
ODM: Mongoose

The system uses four main collections:

- `users`
- `projects`
- `tasks`
- `auditlogs`

---

## 1. Users

Collection: `users`

| Field | Type | Required | Details |
|---|---|---:|---|
| `_id` | ObjectId | Yes | Primary identifier generated by MongoDB |
| `name` | String | Yes | User name |
| `email` | String | Yes | Unique user email |
| `password` | String | Yes | Hashed password using bcrypt |
| `role` | String | Yes | `admin`, `projectManager`, or `teamMember` |
| `createdAt` | Date | Auto | Mongoose timestamp |
| `updatedAt` | Date | Auto | Mongoose timestamp |

### Roles

- `admin` - Full administrative access
- `projectManager` - Project and task management access
- `teamMember` - Access to assigned tasks and task status updates

---

## 2. Projects

Collection: `projects`

| Field | Type | Required | Details |
|---|---|---:|---|
| `_id` | ObjectId | Yes | Primary identifier generated by MongoDB |
| `name` | String | Yes | Project name |
| `description` | String | Yes | Project description |
| `status` | String | Yes | `active` or `completed` |
| `createdBy` | ObjectId | Yes | Reference to `users._id` |
| `createdAt` | Date | Auto | Mongoose timestamp |
| `updatedAt` | Date | Auto | Mongoose timestamp |

### Relationship

`User (1) -> (N) Project`

The `createdBy` field stores the user who created the project.

---

## 3. Tasks

Collection: `tasks`

| Field | Type | Required | Details |
|---|---|---:|---|
| `_id` | ObjectId | Yes | Primary identifier generated by MongoDB |
| `title` | String | Yes | Task title |
| `description` | String | Yes | Task description |
| `project` | ObjectId | Yes | Reference to `projects._id` |
| `assignedTo` | ObjectId | Yes | Reference to `users._id` |
| `status` | String | Yes | `todo`, `in-progress`, or `completed` |
| `priority` | String | Yes | `low`, `medium`, or `high` |
| `dueDate` | Date | Yes | Task deadline |
| `createdAt` | Date | Auto | Mongoose timestamp |
| `updatedAt` | Date | Auto | Mongoose timestamp |

### Relationships

`Project (1) -> (N) Task`

The `project` field connects each task with a project.

`User (1) -> (N) Task`

The `assignedTo` field connects each task with the team member to whom it is assigned.

---

## 4. Audit Logs

Collection: `auditlogs`

| Field | Type | Required | Details |
|---|---|---:|---|
| `_id` | ObjectId | Yes | Primary identifier generated by MongoDB |
| `user` | ObjectId | Yes | Reference to `users._id` |
| `action` | String | Yes | Action performed such as `CREATE`, `UPDATE`, or `DELETE` |
| `entity` | String | Yes | Entity affected, such as `Task` |
| `entityId` | ObjectId | Yes | ID of the affected entity |
| `createdAt` | Date | Auto | Mongoose timestamp |
| `updatedAt` | Date | Auto | Mongoose timestamp |

### Relationship

`User (1) -> (N) AuditLog`

The `user` field stores the user who performed the action.

---

## Validation & Constraints

### Users
- `name` is required.
- `email` is required and unique.
- `password` is required.
- `role` must be `admin`, `projectManager`, or `teamMember`.

### Projects
- `name`, `description`, and `createdBy` are required.
- `status` must be `active` or `completed`.

### Tasks
- `title`, `description`, `project`, `assignedTo`, and `dueDate` are required.
- `status` must be `todo`, `in-progress`, or `completed`.
- `priority` must be `low`, `medium`, or `high`.

### Audit Logs
Audit logs record important create, update, and delete actions performed on system entities.

---

## Security

Passwords are stored as bcrypt hashes and are never stored as plain text.

JWT authentication is used for protected APIs. User identity and role are stored in the JWT payload and are used for role-based access control.

---

## Timestamps

All four Mongoose schemas use timestamps, so the following fields are automatically maintained:

```text
createdAt
updatedAt
```
